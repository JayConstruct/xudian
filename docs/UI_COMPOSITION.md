# UI 组合与声明式模块 v2

UI 组合把模块提供的页面、入口和挂载位置分开。底栏与侧栏由核心壳层渲染；模块不接管壳层，也不能提交任意颜色、字体、尺寸、阴影、CSS 或可执行 UI 代码。

旧导航注册保留原入口 ID，页面适配为模块限定 ID：项目页面为 `app.views.projects.projects`，模块管理页面为 `app.module.manager.modules`；已有模块限定页面 ID 保持不变。入口 ID 和页面 ID 不必相同。

## 使用与布局设置

在设置的“入口与页面布局”中选择手机／窄屏或电脑／宽屏，再选择全局或具体页面，编辑入口位置、顺序、隐藏状态和兼容的页面槽位。窗口小于 820px 使用窄屏配置，至少 820px 使用宽屏配置，不按设备操作系统判断。

- 两套配置独立保存到 `AppSettings` 的 `ui.layout`，与外观偏好 `ui.preferences` 分开。切换配置保留草稿；保存成功后应用，取消不应用；恢复默认只修改当前编辑范围的草稿。
- 全局位置为主导航、顶部菜单、更多、设置常用入口和隐藏；页面槽位另有独立作用域。顶部菜单合并至工作区右上角的单一按钮，包含全部顶部模块入口、页面操作和宿主设置／界面恢复，按布局顺序显示。用户编排优先于模块默认，模块升级不覆盖已有编排。
- 主导航直显上限统计普通入口，**不包含“更多”**。窄屏默认 4，宽屏默认不限制；可调整正整数或不限制。窄屏实际直显数量结合宽度、文字缩放及“更多”占位计算，溢出不改变顺序或删除配置。
- 打开方式与位置独立：工作区切换、详情页和自适应面板不会因移动入口而相互转换。AI 默认顶部入口，宽度至少 1100px 使用侧面板，其余宽度使用浮层。
- 设置、模块管理和布局恢复保留访问途径。模块禁用或槽位移除后保留用户配置；重新可用时可恢复，也可手动清理。

### 编排器预览与诊断

- 入口按全局位置或页面槽位分组，可搜索入口名称、模块、页面、位置及技术 ID；“仅失效 / 待检查”筛选保留需要处理的项目。筛选期间暂停相邻上移／下移，避免对未显示的邻项误操作；显式锚点与置顶／置底仍作用于完整分组。
- 普通模式弱化技术 ID，“显示技术标识”可展开定位信息。槽位类型和打开方式使用功能名称，不直接显示协议枚举。
- “预览草稿”展示当前范围的入口及槽位结构、全部顶部菜单入口及主导航溢出到“更多”的结果。窄屏以 390px、宽屏以 1024px 示意，沿用当前文字缩放，实际布局以设备空间为准。预览不创建模块页面、不执行模块业务逻辑，也不保存草稿，不是实际页面内容截图。
- “查看变更”对比进入编辑器时的配置，同时覆盖两套屏幕配置及全部范围。可恢复单项模块默认，或恢复当前范围默认；恢复操作仍须保存才生效。
- 结构诊断区分目标／宿主不可用、槽位移除、私有槽位、类型不匹配和容量不足。缺少上下文的子页面标为待检查，因为宿主可能在运行时提供上下文；对象存在性、任务与项目关联在运行时核验，不把静态预览当成业务有效性证明。
- 运行时失效页提供原因、对应处理建议和“暂时保留”。“处理挂载”或“重新绑定上下文”定位到实际宿主范围及失败入口；读取上下文失败可以重试。不会自动隐藏、清理或覆盖失效配置。

### 紧凑布局编辑器

- 条目列表使用紧凑可选行，不为每项重复整套编辑控件；位置／槽位分组显示匹配数与总数，并可折叠。工具栏固定在列表上方，提供屏幕配置、范围、搜索、变更与诊断状态；保存始终位于顶部。窄屏用图标切换配置，直显上限通过独立对话框编辑，辅助操作可横向滚动。
- 选择一项后，在宽屏列表旁的单一检查器编辑；窄屏或较大文字缩放时使用可滚动底部面板。编辑器分栏由可用宽度与文字缩放决定，不改变当前选择的窄屏／宽屏配置。这里只编辑结构，不提供画布编辑器。
- “调整位置”和“添加入口或内容”使用可搜索的兼容选项列表，支持名称、模块和标识检索，不展开巨大平铺菜单。模块固定槽位仍可查看，但不能调整位置、顺序或上下文；私有、类型不兼容和固定目标槽位不作为可选挂载目标。
- 检查器提供相邻上移／下移、置顶／置底及“移到指定项之前／之后”。筛选时相邻操作禁用；置顶／置底与锚点选择始终使用完整分组，锚点可搜索未显示的条目，不把筛选结果当成完整顺序。排序与移动保留上下文，单项恢复默认不影响其他条目。
- `UiLayoutPage(initialDraft: ...)` 可接收待审阅的布局草稿；两套直显上限控件从该草稿初始化，“查看变更”仍与进入编辑器时的持久化配置对比，而非与传入草稿对比。传入草稿、预览、上下文修改和默认恢复均不自动保存。
- 保存使用 `saveIfUnchanged(draft, expected: baseline)` 核对数据库中的基线，不仅检查可能过期的 provider 状态。保存冲突或失败时保留草稿，不覆盖其他操作已保存的配置；编辑会话通过 `uiLayoutEditorSessionsProvider` 登记，规范化配置与基线不同或直显上限输入无效时标记为未提交，退出时注销。

## source、Schema 与模块包

公开契约为 [declarative-module-v2.schema.json](../packages/schemas/declarative-module-v2.schema.json)，通过标准引用保留 [版本 1](../packages/schemas/declarative-module-v1.schema.json)，并复用其 `views / fields / templates / rules` 资源定义。客户端没有通用 Schema 执行器，实际执行协议以 `DeclarativeModuleParser`、`DeclarativeAppModule` 和 UI 组合运行时为准。

三个版本号不要混淆：

| 字段 | 含义 |
| --- | --- |
| `formatVersion: 2` | 模块 source 使用页面组合协议；版本 1 仍受支持 |
| `manifest.version` | 模块自身的语义版本，例如 `1.0.0` |
| `packageFormat: 1` | 模块包外层格式；没有改为 2 |

每个 v2 模块必须声明 capability `ui.composition`、`ui.registry` 及权限 `ui.register`。包含 `task.list` 视图时另需 `tasks.query` capability 和 `tasks.read` 权限；纯 UI 容器不需任务权限。公开槽位只是 UI 接入点，不提供宿主的查询或命令权限。

Schema 严格拒绝未知顶层、manifest 及组合字段，包括页面、槽位、入口和挂载中的任意视觉样式。引用存在性、资源／入口 ID 唯一性、同模块及跨模块槽位兼容、上下文、容量和权限另由解析器／运行时检查；通过 Schema 不等于一定能执行所有挂载。Schema 默认值是说明，不应由工具自动把省略的 `entry` 补成入口。

### 页面与槽位

`pages` 的每项必须有本地 `id` 和 `title`；ID 规则沿用 v1。

| 字段 | 行为 |
| --- | --- |
| `kind` | `view`（默认）要求 `view` 引用存在的任务视图；`container` 不能声明 `view`，只承载槽位 |
| `entry` | 显式 `{}` 或入口对象才注册入口；省略、`null`、`false` 都不注册；`true` 无效 |
| `slots` | 页面定义的槽位列表，本页槽位 ID 必须唯一 |
| `requiredContext` | 需要的 `taskId` 和／或 `projectId`；不授予数据权限 |
| `retainPosition` | 默认 `false`；`true` 保留局部页签／滚动位置，仅本次运行有效，重启清空 |
| `icon / selectedIcon` | 使用客户端支持的图标名称，不是自定义图标代码 |
| `quickAdd / quickAddDefaults` | 全局工作区快速添加声明；嵌套页面不隐式接管壳层快速输入 |

版本 1 保持所有页面自动进入主导航，且 `layouts` 必须省略或为空。版本 2 不把子页面自动添加到全局导航：显式 `entry: {}` 使用页面 ID 和标题，默认放入主导航，以工作区方式打开。

槽位必须有 `id` 和 `label`，可声明：

| 字段 | 默认及约束 |
| --- | --- |
| `kind` | `entries`：入口按钮；`tabs`：页签内容；`sections`：纵向内容区，默认 `entries` |
| `public` | 默认 `false`，仅本模块可用；`true` 允许其他模块的兼容贡献 |
| `editable` | 默认 `true`，允许用户编排；`false` 表示模块固定槽位 |
| `capacity` | 可选正整数；不声明则无显式槽位数量上限 |
| `requiredContext` | 槽位额外要求的任务／项目上下文 |

### 入口与 `layouts` 挂载

页面入口对象支持 `id / label / opening / placement / content / targetPageId / slotId / order`。它的内容页面就是当前页面；`targetPageId` 是挂载宿主，不是另一个要打开的页面。

`layouts` 的每项要求 `id / pageId / label`，支持 `content / opening / placement / hostPageId / slotId / order`。`pageId` 是贡献的页面，`hostPageId` 是宿主。入口与 layout 的本地 ID 在同一模块内不能重复。

- 页面引用使用本地 ID，或完整的 `模块ID.页面ID`，例如 `example.ui.host.workspace`；跨模块槽位由宿主页面引用和本地 `slotId` 共同定位。
- `opening` 可为 `workspace`（默认）、`detail`、`adaptivePanel`；`placement` 可为 `main`（默认）、`header`、`more`、`settings`、`hidden`、`page`。
- `placement: "page"` 必须提供宿主引用与 `slotId`；全局位置不能携带宿主／槽位字段，也不能声明 `content: true`。
- `content` 默认 `false`，用于 `entries` 槽位的入口按钮；`true` 用于 `tabs / sections` 槽位的嵌入内容。一个入口／贡献只有一个挂载位置，同一页面可由不同入口／贡献引用。
- `order` 默认 0，接受整数；只控制排列，不表达视觉布局。

## 嵌套、上下文与失效

子页面可继续公开自己的槽位。内容按需加载，页签只激活当前内容，退出或隐藏后释放订阅；局部位置保留不意味着把隐藏页面及订阅永久保活。页面位置按挂载路径和上下文隔离，不自动缓存业务表单数据。

嵌套深度没有硬上限，达到 8 层提醒调整布局。循环内容嵌套停止对应分支并展示原因，不关闭其他分支；普通页面跳转与内容循环不是同一种约束。

`PageContext` 传递任务／项目标识；页面和槽位的上下文要求都要满足，实体是否有效仍需检查。缺少上下文、宿主不可用、槽位删除、类型不兼容或容量不足时展示失效原因，不把旧内容作为有效结果继续操作。

用户可以“暂时保留”配置，也可以“处理挂载”进入布局设置补充上下文、调整位置或移除挂载。“移除挂载”把当前贡献改为隐藏，不删除页面或业务数据；已不可用的入口还可清理失效配置。条件恢复后，保留的有效配置可重新使用。跨模块贡献继续以自己的 `ModuleContext` 检查业务权限，不能继承宿主权限；公开挂载不自动成为强模块依赖。

## 界面标注与原生示例

设置中开启“界面标注模式”后，为已登记的可见关键区域和控件显示 `U01` 等会话编号与名称。标注覆盖层不改变原布局；可拖动控制条、暂时隐藏或退出，默认关闭且不跨重启保留。

点击标注可以查看和复制稳定 UI ID、模块、页面路径、槽位及作用。`U` 编号只用于当前会话，同一稳定 ID 的重复实例可有不同会话号；不要用编号代替长期定位。复制仅使用注册时提供的静态元数据，不提取任务正文、输入内容、业务对象 ID 或密钥，不自动截图、上传或发送给 AI。新增标注调用必须遵守这一元数据约束。

模块管理中的“UI 示例”（`app.ui.examples`）与“UI 示例贡献”（`app.ui.contributions`）是可开关的原生模块，默认不增加主导航。前者提供组件和槽位页面，后者向公开槽位提供内容与上下文失效演示；都只申请 UI 注册权限，不读取或写入真实业务数据。其原生控件丰富度不代表声明式模块已支持所有控件。

## 两个 JSON source 示例

- [ui-slot-host-v2.json](../packages/examples/ui-slot-host-v2.json)：纯 UI `container`，显式 `entry: {}` 注册主导航入口，公开 `tabs` 和 `sections`，声明运行期间保留局部位置，不申请任务权限。
- [ui-slot-contributor-v2.json](../packages/examples/ui-slot-contributor-v2.json)：`task.list` 只读视图，声明 `tasks.read` 与 `tasks.query`；页面 `entry: false` 不增加导航，两个 `layouts` 分别以 `content: true` 挂入宿主公开页签和纵向内容。

这两个文件都是**模块 source，不是可直接文件导入的模块包**。贡献示例会读取本机真实任务，仅不写入；它与不读取真实数据的原生 UI 示例不同。示例不自动创建演示任务，无任务时显示空状态。

使用方法：

1. 在 AI 模块生成页展开高级 JSON，粘贴完整 source，查看 JSON 变更并确认安装；无需调用模型生成。先安装宿主，再安装贡献模块，可在“公开槽位工作区”观察两种内容挂载。
2. 也可以先安装贡献模块。示例的 `dependencies` 为空，缺少宿主不会被强依赖阻止；挂载保留为失效项，安装宿主后恢复，也可在布局设置调整。
3. 如使用模块管理的“导入模块包”，需按 [module-package-v1.schema.json](../packages/schemas/module-package-v1.schema.json) 封装 source 到 `module`：外层 `packageFormat: 1`、本地 `release.channel: "local"`，`integrity.algorithm: "sha256"`，摘要必须由现有验证器所用的 canonical JSON 算法计算。不能用任意占位摘要，也不能对 source 文件原始文本直接求摘要；本地包不带签名，市场包仍遵守原有审核与可信发布者签名规则。

模块包外层格式保持 1，仅内层 `module.formatVersion` 使用 2。上述 source 文件不能直接交给 package 导入，也不能在 source 顶层加入 `$schema` 或包字段，因为解析器严格检查顶层键。
