# 拾光导入地点处理

设计稿见 [SVG](shiguang-location-options.svg)。本稿在功能实现前生成，沿用现有模块声明式表单与导入预览，不增加宿主专用页面。

风格参考本机既有模拟器截图 `dist/verification/platform/legacy-20261029/android-shiguang-captured-config.png`、`android-shiguang-1.7-installed-home.png`，以及 `host_dialogs.dart` 中当前全屏表单实现：灰白底、柔和填充输入框、蓝紫主色、圆角按钮、顶部返回／关闭。地点方式复用当前 `select` 下拉框，校区名称复用 `multiline`，预览仍复用模块 `column`／`sectionHeader`／`text`／`button`。不新增独立视觉体系，实际透明度与全局主题保持一致。

- 学期确认增加地点处理：默认保留完整地点，也可选择去掉校区或不导入地点。
- 去掉校区时，自动建议地点开头可识别的校区名称，允许手动修改，一行一个。只按填写的完整文本处理地点开头或末尾，不按模糊关键词删除教室。
- 导入结果提供“处理地点”入口与原始地点到结果的示例。地点设置可反复修改、取消、恢复完整地点，原始采集结果不被覆盖。
- 修改地点仅重建草稿、清除旧变更计划；保存仍由课表模块的实际变更确认完成。安排来源标识使用原始地点生成，切换处理方式不制造新安排。
- 模拟器验收发现，原有配置后自动跳转到课表会结束拾光页面会话，用户无法返回原草稿再次处理地点。因此配置完成先留在拾光预览，“查看实际变更”作为显式下一步；全屏配置的提交按钮相应为“生成导入预览”。

## 取消实际变更后继续调整

新增流程稿见 [取消与返回 SVG](shiguang-import-return-flow.svg)，先于本轮导航修复生成。查看实际变更直接打开“导入与备份”详情，保留下层拾光会话，不切换工作区。用户取消实际变更后，通过工具栏或系统返回回到同一草稿，原始地点、地点方式、填写的校区名称及学期配置仍在；再修改地点并查看实际变更时，重新生成计划。取消仅清除课表模块的预览，不保存课程。上下文只传计划标识，原始采集与可恢复草稿留在拾光页面。

校区识别采用保守原则：自动候选含数字或明显教室／楼馆片段时不猜测，提示手动填写；只按明确校区文本处理，保留 `-101` 等教室编号中的负号，候选名称最多30个。
