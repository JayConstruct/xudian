# 模块 UI、动画与手势扩展方案

本文件保留基于宿主 API 1.49.0 的设计与后续范围。首批 A/B 的实现使用 API 1.50.0，已实现协议以 [页面 SDK](../sdk/PAGES.md#api-150-的属性动画与滑动操作) 为准；C/D 仍是后续设计。功能检查、设备与性能结果必须单独记录，不由实现状态推断验收成功。

目标是在保持 Flutter/Dart 宿主与 JavaScript/QuickJS 模块架构的前提下，使常见页面布局、动画参数、滑动操作和交互流程可以独立更新模块。页面、字段、文案和业务规则归模块；宿主实现通用渲染、连续交互、导航和无障碍。

## 1. 决策与范围

采用“模块声明、宿主执行、结果回传”。一次页面声明描述效果和交互规则；逐帧插值、指针跟踪、命中测试和回弹在 Dart/Flutter 内执行。模块在离散操作发生时接收事件，沿用已有服务调用和数据提交机制。

| 范围 | 本方案决定 |
| --- | --- |
| 布局与样式 | 优先扩充现有组件配置；缺少通用表达时才增加节点 |
| 属性动画 | 新增有类型的目标属性与有限曲线，复用原生动画控制器 |
| 手势 | 开放常见交互预设和受约束的参数，逐步支持组合 |
| 本地交互状态 | 宿主持有临时视觉状态；模块持有业务状态和持久偏好 |
| 高频通信 | 不向 QuickJS 逐帧发送指针或动画事件 |
| 更新边界 | 新底层能力需更新 APK；已支持能力的组合和参数只更新模块 |
| 暂不建设 | 任意 Flutter 类加载、任意 JS 绘制回调、可执行表达式、着色器脚本、完整 HTML/CSS 引擎 |

首批交付限定为：既有按钮的按压反馈配置、状态切换动效、横向滑出操作按钮。拖动排序、通用 pan/pinch 和组合时间轴均放在后续独立评审，不是首批依赖。规划看板已有缩放和时间拖动保持现有协议，作为回归基线。

优先级依据是减少重复实现和 APK 更新，不是增加节点数量：已有组件能表达时只补参数；可复用的属性变换才新增包装节点；有完整交互生命周期的滑动操作才新增交互节点。第一版不新增 SDK RPC、页面响应字段或全局动画调度框架。

| 模块作者要修改什么 | 首批落地后的更新方式 |
| --- | --- |
| 已有组件布局、文案、按钮业务、主题配置 | 使用原协议，只更新模块 |
| 状态变化后的位移／缩放／透明度及动画时长／曲线 | 使用 `motion`，只更新模块 |
| 按钮按压幅度与时长 | 使用 `button.feedback`，只更新模块 |
| 滑动方向、展开宽度、阈值、松手动效与操作列表 | 使用 `swipeActions`，只更新模块 |
| 新绘制属性、手势识别算法、跨列表拖动、系统能力 | 仍需扩展宿主并更新 APK |

所有“只更新模块”均以已安装宿主支持对应最低 API 为前提；首批不承诺任意页面与任意手势均可动态实现。

## 2. 与现有能力衔接

当前 `transition` 支持 fade、scale、slide、page，已有折叠、稳定列表差量及页面前进／返回；其行为继续保持。`plannerBoard` 已由宿主处理双指缩放，结束后回传结果，可作为新连续交互的模式参考。

| 现有位置 | 拟改动职责 |
| --- | --- |
| `client/lib/core/module_host/script_page.dart` | 接入新节点；其直接渲染的 `button` 接入反馈；解析绑定并沿原路径派发事件 |
| `client/lib/core/ui/script_transition.dart` | 保留兼容入口，按需复用新动画基础设施，不改变旧参数默认值 |
| `client/lib/core/ui/` 下新增通用文件 | 类型化动画配置、动画控件、滑动操作控件及局部状态；失活信号复用现有页面生命周期 |
| `client/lib/core/ui/ui_component.dart` | 公共内置按钮接入同一反馈控件；与 script_page 的直接按钮分别验证，不假定两者共用入口 |
| `client/lib/core/ui/ui_pack.dart`（后续） | 核心能力稳定后扩展配方，继续保留必要槽位与事件端口 |
| `packages/schemas/` 下新增契约 | 新节点的 JSON Schema、版本与有效／无效样例 |
| `packages/xquickjs/lib/xquickjs.dart` 的 SDK 源码 | 按需提供纯构造辅助函数；初期可直接返回节点，不新增逐帧 RPC |
| `packages/modules/app.ui.examples/` | 可操作示例、协议说明及异常／取消场景 |

新增解析器不继续堆入 `script_page.dart` 的分支。新增 Schema、Dart 校验器和文档使用同一组契约样例做一致性验证；不能只校验模块清单而忽略脚本运行时返回的节点。

Schema 描述模块声明（包括合法绑定）；Dart 在绑定解析后再校验类型与范围。两层样例成对验证，避免把动态绑定误判为数字类型错误。新节点配置先完整校验，再建立监听和可操作控件；错误隔离到对应节点，错误分支不可点击。旧节点的验证策略不在本轮重写。

处理链固定为“解析绑定 → 校验新配置 → 按身份协调局部状态 → 构建控件 → 原生帧更新”。节点配置只在页面结果或已解析的组件实现发生变化时比较；不在指针回调序列化／哈希整棵树。首批只抽取新节点所需代码，避免顺带改造整个页面渲染器。

## 3. 布局与属性动画契约

先盘点已支持的间距、弹性行、卡片、固定底栏、文本及响应式配置；新增字段附在对应组件。首批继续使用现有布局节点，不预先增加层叠和约束语言；后续由明确页面需求驱动。局部动效不能覆盖受保护的宿主导航、审核或恢复入口。

新增 `motion` 包装节点，首期限定为绘制属性：`opacity`、`translateX`、`translateY`、`scale`。位移使用逻辑像素，缩放以中心为原点；先统一使用等比缩放，属性缺省分别为 1、0、0、1。旋转等属性等实际需求出现再扩展。入场、退场、折叠继续使用既有节点，避免维护两套生命周期。

以下是拟议语法，不能直接用于现有宿主：

```javascript
{
  type: 'motion',
  key: 'task:42:feedback',
  target: {
    opacity: 1,
    translateY: 0,
    scale: {bind: ['state', 'cardScale']}
  },
  timing: {duration: 180, curve: 'easeOut'},
  child: {type: 'card', children: [{type: 'text', text: '任务内容'}]}
}
```

- `target` 的各数值字段可以使用现有路径绑定；在页面结果应用时解析为具体值。`type` 和 `key` 使用静态非空字符串；首批 `timing` 使用字面量。动画帧中不重新解释绑定或调用脚本。
- 示例的 `state.cardScale` 必须由模块初始化为合法数值。首次挂载直接显示 `target`；同身份目标变化从当前插值值继续，相同目标不重播。只改时长／曲线且目标未变时，当前动画按原配置完成，下次使用新配置。惰性项销毁后重新挂载直接显示当前目标。
- 第一版时长为 0～2000ms，默认 180ms；曲线采用 `linear/easeIn/easeOut/easeInOut`，默认 `easeOut`。所有数字必须有限；透明度 0～1，缩放 0.1～4，位移绝对值不超过 4096dp。越界或未知字段报错，不静默夹取。它们是拟议协议边界，不是性能承诺。
- 同一 `motion` 的属性共用一个进度控制器，执行顺序为中心缩放、位移，再应用透明度。绘制变换不改变父布局占位；命中坐标跟随变换，但可操作区域限定在父级允许的命中范围，不能借位移扩大到相邻控件或导航区。绘制沿用父容器／工作区的裁剪边界，不为每个 motion 自动增加裁剪图层。
- 需要改变布局高度时继续使用已有 `transition.collapse`。显式嵌套按 Widget 树组合变换，各节点只写自身属性；不跨树查找或修改子节点的动画控制器。按钮反馈作用于按钮内部，滑动位移属于滑动容器。嵌套成本纳入同一页面预算，不为防止组合而添加整树扫描。
- `motion` 本身不改变可见性、焦点或语义。需要隐藏内容时使用既有可见性节点，由宿主同步撤出命中、焦点与无障碍；不能用透明度代替隐藏。
- 退出动画继续由 `keyedList` 等持有退出生命周期的容器负责。已从树中删除的普通 `motion` 不额外复活旧控件。
- 系统或应用减少动态效果时立即到目标值。初期不提供动画结束业务回调，以免动画取消影响业务执行。
- 后续有明确需求再增加并行／顺序轨道和有限弹簧预设；各阶段单独定义冲突、时长及取消语义。

新契约的 `linear/easeIn/easeOut/easeInOut` 分别固定映射到 Flutter 同名曲线，不随宿主主题切换；旧 `transition` 继续使用原曲线。duration 为整数毫秒，target 为必填对象且至少声明一个合法属性，child 为必填单节点；未声明属性使用默认值，显式 null 或无效绑定报错。`timing` 和 `settle` 共享同一解析器，避免同名参数在不同节点表现不同。

## 4. 常见手势契约

按压反馈增加到已有 `button` 配置；滑动操作使用专门的 `swipeActions` 节点。两者不统一成任意 `interaction.preset` 容器，避免首批承担不存在的通用状态机和冲突组合。

| 能力 | 可配置项 | 脚本事件 |
| --- | --- | --- |
| `button.feedback` | 按压缩放、时长 | 实际点击时使用原有事件与 command 处理 |
| `swipeActions` | 起始／末尾侧、操作区宽度、打开阈值、动作列表 | 点击某个动作时发送该动作事件 |
| 排序（后续 C 阶段） | 稳定 key、范围、启用、拖动手柄 | 释放后发送源 key 与目标锚点 |
| 通用 pan/pinch（后续 D 阶段） | 轴、边界、吸附、缩放范围及结果事件 | 结束时发送最终值；首期不定义语法 |

`button.feedback:{pressedScale:0.98,duration:100}` 读取已有按钮的按压状态，不额外套一个竞争点击的父控件；省略时保持当前反馈。拟限制缩放 0.9～1、时长 0～300ms；减少动态效果时保留既有颜色／焦点反馈，不播放缩放。触控和键盘激活使用同一动作，禁用或取消时复位，命中框维持原尺寸。首批只支持宿主原生按钮和内置公共按钮实现；不支持的自定义 UI 包回退到自身现有反馈，不能丢失操作。长按和双击待实际需求再扩展。

feedback 使用字面量配置，提供该对象时缺省值为 `pressedScale:0.98,duration:100`。直接节点为 `button.feedback`，公共按钮调用为 `ui.component('ui.button@1',{props:{feedback:...},events:...})`。公共契约 Schema 和内置实现同时更新；自定义配方暂不要求消费这个可选视觉字段。直接按钮的 disabled、interrupt、输入排队与 command 路径均保持既有语义，不重新推导 onPressed。

```javascript
{
  type: 'swipeActions',
  key: 'task:42:actions',
  enabled: true,
  side: 'end', extent: 96, openThreshold: 0.4,
  settle: {duration: 180, curve: 'easeOut'},
  actions: [{
    label: '编辑', icon: 'edit',
    event: {type: 'editTask', id: '42'}
  }],
  child: {type: 'card', children: [{type: 'text', text: '任务内容'}]}
}
```

`side` 默认 `end`，`enabled` 默认 true，`openThreshold` 默认 0.4；`start/end` 跟随文字方向。`actions` 为 1～3 项，`extent` 为必填且限定 48～240dp，并须至少等于动作数乘以 48dp。每个动作使用必填 label、event，可选合法 icon 和 disabled。首期只支持单侧，按释放位置占 extent 的比例判断打开／关闭，阈值为 0.2～0.8；速度不决定动作执行。

`settle` 复用 motion 的时长／曲线契约，默认 180ms、easeOut；模块可独立调整松手动画，减少动态效果时立即到终态。`enabled`、动作 disabled 和 revision 可使用现有绑定，其他配置使用字面量；event 的绑定规则沿用现有页面事件。`enabled:false` 禁用滑动、动作菜单及其中的动作，child 是否可点击由它自身配置控制。

容器始终提供带无障碍名称的“更多操作”入口，使用相同动作列表和至少 48dp 的触控区；只在存在可用宽度时与内容并排，否则放在内容下方。滑出按钮与菜单共用同一派发锁。大字号导致动作区容纳不下、内容含复杂交互或自定义组件能力未知时，只使用这个菜单并保留完整 child，不启用横滑。此为功能等价回退，不是非法配置；调试诊断标明回退原因。

滑开和收起完全在宿主内进行，不调用脚本。滑动或结束动画中，内容点击与动作激活均暂停；稳定打开后动作可激活，点击内容只关闭并消费该次点击，关闭状态的内容点击继续走原事件。菜单打开时先收起滑动区；两种入口不会同时拥有焦点。用户点击动作后先锁定派发、关闭操作区，再发送一次事件，派发不等待关闭动画完成；脚本失败后可重新打开并重试。滑动本身不删除记录，不产生自动提交权限。

### 手势竞争与可访问性

- 使用 Flutter 手势竞争机制；纵向列表中的横滑只竞争横向意图，纵向拖动交给列表。方向判定和触控容差由宿主统一维护，第一版不下放任意优先级。
- 首批只有已确认的静态内容组合可横滑，可含普通点击卡片和按钮。可编辑输入、可选择文本、嵌套滚动、另一连续手势根节点及未知槽位走菜单回退。分类基于解析后的实际组件实现，不能只看脚本节点名；配方切换或组件解析修订变化时取消交互并重新分类。不需要扫描已有页面所有节点，仅在新滑动子树构建时归纳并缓存类别。
- 同一列表实例最多打开一行；无列表容器时使用当前页面挂载实例的默认作用域。作用域由宿主生成，不能用模块提供的字符串控制另一页面。父列表开始滚动、离屏回收或打开其他行动作区时关闭当前行。
- 系统边缘返回由宿主路由处理，滑动节点不新增返回拦截器；返回或关闭页面时一并清理局部动作区。桌面 Escape、局部关闭按钮和点击内容可单独收起，避免改变既有返回层级。
- 读屏与键盘可通过操作菜单执行同一组动作，语义动作也视为用户操作；减少动画仍保留必要跟手位移，释放后直接到最终位置。
- 识别后新增第二根手指、系统取消或窗口失焦时关闭动作区，不执行动作；禁用与进入页面 busy 时同样取消。后续 C 阶段拖动排序由手柄或长按启动，自动滚动由宿主计算。
- 关闭状态的滑出按钮从命中、焦点和无障碍树移除；展开时提供动作名称和关闭入口。键盘打开菜单后，取消返回“更多操作”按钮；动作导致导航时由新页面接管焦点。因滚动或失活关闭时不重新请求焦点，也不抢回键盘。

## 5. 状态、回传与授权

分开管理三类状态：模块业务状态（真实记录、选择结果）、模块持久偏好（缩放等）、宿主临时状态（手指位置、动画进度、动作区展开）。纯视觉展开不写数据库，也不触发整页 busy。

首批滑动视觉状态机为 `closed → tracking → settling → open/closed`，点击动作后收起为 closed；另用派发锁防止同一次工作流完成前重复激活，视觉收起不代表解锁。动画节点只持有当前值与目标值，不增加通用业务状态机。复用现有实例、页面租约和上下文失效信号；局部交互序号仅用于丢弃失效的动画／回调。

新增有状态节点要求稳定 key。身份由模块实例、页面挂载路径、父级稳定身份、节点类型和 key 共同确定；同级重复 key 拒绝，跨页面同名 key 不共享状态。新父容器下的相同 key 视为新实例。节点事件、动作集合、禁用状态、手势参数和模块显式提供的可选 `revision` 组成交互配置；revision 为不透明字符串或整数，宿主不猜测业务记录版本。其变化取消当前交互；普通文字更新不取消。

revision 只属于 `swipeActions` 的可选字段，普通 motion 不需要它。交互配置是绑定解析后的不可变值；方向、可用尺寸、字体缩放或组件实现变化导致现有几何／分类不再有效时也取消。页面 epoch 用于丢弃过期页面结果，不直接充当节点身份，避免每次普通刷新重建动画。

| 情况 | 处理 |
| --- | --- |
| 普通页面刷新、相同身份和相同交互配置 | 保留当前视觉状态；更新非交互内容；motion 按新目标插值 |
| 节点删除、身份／交互配置／revision 变化、禁用 | 滑动区关闭，取消在途回调；数据预览恢复已确认状态 |
| 切页、页面失活、模块升级／停用、进入后台 | 撤销局部交互令牌、清理指针与覆盖层、停止动画；控制器是否 dispose 按节点是否销毁决定 |
| 取消手势 | 恢复已确认状态，不提交，不向脚本补发业务动作 |
| 结果处理失败或既有工作流失败 | 清除临时预览、恢复已确认显示；失败提示不宣称写入已撤销 |
| 已提交后页面失活或响应丢失 | 真实数据不回滚；重新进入查询实际结果，复用服务幂等机制 |

后续 C 阶段排序事件应包含源 key、目标 before/after 锚点与列表修订号；不只传容易失效的数组下标。模块验证实体存在性、排序范围和最新数据，再走现有准备／审核／提交。拖动预览只重排宿主显示，不先写真实数据。

首批沿用 `{state,tree,...}` 页面结果及现有调用 epoch、上下文和实例校验，不增加脚本结果确认字段。后续排序优先将一次操作与既有页面调用关联：有效返回的权威树替换预览，错误则清除预览并重新查询，树中实际顺序决定显示。业务取消返回原顺序即可；成功通知来自真实提交，不来自动画或树形差异。

不为等待用户审核设置额外的手势超时。页面可以在等待期间显示局部预览，但页面失活立即清理；清理视觉资源不等于取消已进入提交的事务。只有未来出现多个并发局部操作、现有调用身份不能可靠关联时，才单独设计新的结果协议。

首批不建立待确认结果表。一个滑动节点的派发锁从激活持续到对应页面工作流结束或节点销毁，不在关闭动画完成时解锁；同一内容的菜单与滑出动作复用这把锁，避免双重激活。现有页面 busy 和调用队列继续生效，不承诺局部异步更新。后续排序每节点最多保留一个预览，拖动中影响该交互的外部数据变化采用取消并刷新策略。

新事件继续走既有权限与审核。已有按钮增加 feedback 后，原 `command` 及语义激活行为保持不变。新增滑动动作第一版仅支持普通 event，不自行引入 command 或规划时间手势授权；将来接入必须复用原生能力绑定与完整输入／写集检查。动画、阈值到达和脚本伪造事件不产生授权。

## 6. 性能预算与资源管理

以下为拟议验收目标，尚未实测，不应写成当前性能结果。

| 项目 | 设计与验收要求 |
| --- | --- |
| 连续拖动／动画 | 每帧 QuickJS 调用数为 0；纯视觉展开整个过程为 0 |
| 离散激活 | 一次按钮或菜单激活至多派发一次对应页面事件；按操作标记统计，后台刷新及业务服务调用另计 |
| 更新范围 | 绘制属性只更新对应节点，静态 child 复用；不重建整页或重新查询业务数据 |
| 解析 | 页面声明变化时验证／解析；按页面及节点复用配置，不缓存无限份历史树 |
| 离屏 | 不创建未挂载项的控制器；列表回收时销毁；保活项复用容器可见性信号，无信号时允许有限动画自然结束，不增加逐帧全屏可见性扫描 |
| 资源 | 页面失活释放交互资源；记录控制器数、缓存大小、跨桥次数和取消原因 |

协议硬约束与宿主调度参数分开：声明嵌套继续不超过 32 层，数值边界按节点契约校验；每个滑动节点最多一个连续手势所有者。新增动效暂以每个活动页面挂载实例最多 64 个同时运行的控制器作为内部实验上限，不写入 SDK 保证；每个 motion 共用一个控制器且按需启动。用页面作用域计数管理，不构建通用调度器。实施时测多个嵌入模块共用工作区的总量，冻结候选前校准限额；存量动画不在首批被强制纳入新限额。

达到内部预算后，新的装饰动效直接落到目标状态；正在进行的用户跟手不被抢占，松手动画可立即到终态。失活时同步取消指针、关闭菜单、清理局部状态，将视觉值落到目标并停止 ticker；保活页面可保留已停止的控制器，页面销毁时 dispose，恢复不重播。活动计数归零与对象释放分开统计。预算降级有诊断计数，不伪装成正常播放。

第一阶段只允许单段有限动画，不提供无限循环、任意离屏滤镜或无界自定义绘制；不提前规定尚未设计的组合轨道数。透明度仍可能增加绘制成本，不能因为不跨桥就视为免费；仅对测量证明有效的子树使用 RepaintBoundary，避免每行强制建图层。资源降级只影响装饰，不能丢弃业务动作或隐藏操作入口。

对照实验分为两组：新增效果与相同视觉和轨迹的直接 Flutter 实现对比，用于测协议开销；已有页面与修改前版本对比，用于测回归。固定设备、刷新率、数据、profile 构建和操作轨迹，记录温度及系统负载，交替测量顺序。每场景预热后测三轮各 30 秒，冷进入单独记录；保存原始样本与每轮结果，样本不足标注未定，不能只取最好一轮。

报告 UI 和 raster 帧耗时 p50/p95/p99、超帧预算比例、首屏时间、内存、跨桥次数及节点重建次数。只统计场景活动区间内产生的帧，记录样本数；空闲时间不补成零耗时帧。另用固定事件数统计输入到对应状态首帧的延迟：先验证事件与帧序号的关联，无法准确关联则标记缺失，不拿下一次任意帧代替。该指标不含触屏硬件和显示扫描延迟，不作为端到端触控延迟。

暂定验收目标：目标刷新率为 R 时帧预算 B=1000/R ms；每轮 UI 与 raster 的 p95 各低于 B，相对对照的 p95 增量不超过 `max(0.5ms, B×5%)`，任一阶段超过 B 的帧比例不超过 1%，且相对对照增量不超过 0.5 个百分点。报告 p99 和长帧原始记录，避免 p95 隐藏少量严重卡顿。60Hz 与 120Hz 分别约为 16.7ms 与 8.3ms。这里的超预算帧是 FrameTiming 代理指标，不等同于平台实际丢帧数。

这些是待基准校准的工程门槛，不是已测结果或 SDK 承诺。最慢目标设备须在实施前明确并记录；若波动接近差值或任何一轮失败，先定位和复测，不以三轮平均掩盖失败。基线已超预算时保留绝对失败，不能仅以相对增量通过。没有真机数据时不能给出性能通过结论。

场景包括单卡片、20 个可见项、1000 项惰性列表、连续快速反转、滚动与横滑竞争、已有密集规划看板、后台恢复。重复打开／关闭 50 次后属于已销毁页面的控制器、监听和租约计数为零；区分刻意保留的路由状态与泄漏，预热后按相同 GC 采样条件检查内存趋势。日志仅记录节点类型、计数与耗时，不记录业务正文。真实数据与动画关闭时一致。

Flutter 官方建议缩小重建范围、复用动画不变的子树并谨慎使用离屏绘制；本方案据此把逐帧工作留在局部原生控件。参考 [性能实践](https://docs.flutter.dev/perf/best-practices)。性能结论使用真机 profile 模式，模拟器只承担功能验收；参考 [性能测量](https://docs.flutter.dev/perf/ui-performance)。手势竞争遵循 [Flutter 手势机制](https://docs.flutter.dev/ui/interactivity/gestures)。

## 7. 版本、UI 包与回退

- 当前协议继续运行。首批能力最低 `hostApi` 为 `^1.50.0`；后续新增能力按实际发布分配最低版本，模块必须声明对应范围。
- 首期用最低版本约束保证兼容，不新增能力查询 RPC。旧宿主拒绝不兼容模块并提示升级，不静默忽略必要节点。需要服务旧宿主时发布使用旧节点的兼容模块版本。
- 未来若引入运行时能力查询，只有已支持该查询协议的宿主才可使用条件回退；不能假设旧解析器会跳过未知节点里的 fallback。
- UI 包可以提供动画样式和装饰预设，业务模块绑定真实事件。UI 包必须保留必需槽位、可访问操作与事件端口，不能新增业务动作、改变 command 输入或扩大命中区域到宿主控制区。
- UI 包接入放在核心节点稳定之后；脚本页面与 UI 包共用动画配置校验和执行器，允许的节点集合仍各自受协议约束。
- 模块修改递增 `module.json` 版本，不覆盖同版本包；APK 更新不代表已安装模块已更新。只有首次安装默认资源变化才同步更新预装包。

## 8. 分阶段实施与完成条件

| 阶段 | 范围 | 完成条件 |
| --- | --- | --- |
| A：基础与纵向样例 | 契约、`motion`、`button.feedback`、示例与计数 | 参数验证、反转／减少动画／取消测试通过；既有 command 不回归；真机对照无超标回归 |
| B：常见操作 | `swipeActions`、滚动冲突、操作菜单与读屏替代 | 点击、横滑、纵滚、返回、关闭／重开和业务失败均通过；滑动过程无 JS 调用 |
| C：数据相关交互 | 单列表排序、复用页面调用关联、边缘滚动、并行数据变化处理 | 预览与真实数据一致，取消／过期／失败不误写；不假定新增响应协议；提交与审核保持原规则 |
| D：扩充复用 | 按需开放通用 pan/pinch、有限组合动画、UI 包接入 | 至少两个独立模块有需求；补齐组合冲突、预算和兼容测试再发布 |

建议 A+B 作为首个可交付范围；它能使常见反馈和滑动操作通过模块调整，并验证性能与协议是否合适。C、D 不作为首批必须完成的前置条件。现有复杂规划交互抽取通用基础设施单独推进，不能借此把业务流程搬入宿主。

首批实施顺序：先固定契约样例与基线场景，再做 motion 和按钮反馈，最后接滑动控件与生命周期；三者稳定后再定宿主版本及示例模块版本，完成一次候选包检查和设备验收。局部测试随开发运行，不反复执行相同完整回归。示例使用模拟数据，至少覆盖一个状态变更和一个可取消操作，不将业务模块迁移作为前置条件。

候选冻结前必须完成三项：将本文默认值和曲线映射固化到契约样例；登记最低性能目标设备与校准门槛；依据测试列出可横滑及仅菜单回退的组件集合。使用小型等效 Flutter 夹具做性能对照，不复制整个业务页面。首批完成以“契约样例、相关测试、设备交互、模块独立更新、真机性能”五类证据齐备为准；任何缺项标记部分完成，不以文档完整代替实现完成。

## 9. 测试、设备验收与交付

契约测试覆盖合法／非法枚举、非有限值、超限、未知字段、重复 key、绑定解析前后、旧节点兼容以及 Schema/Dart 行为一致性。Widget 测试覆盖动画反转、不重播、命中／焦点、减少动态效果、横滑与纵滚竞争、第二指取消、页面 busy、动作事件更新、配方切换、宽度／字号变化、列表回收、迟到响应及菜单回退。QuickJS 集成测试证明一次离散操作只调用一次工作流，未引入逐帧桥接及权限绕过；直接按钮和公共内置按钮分别验证 feedback，原 command、interrupt 和输入排队路径按实际入口回归。

优先扩展现有 `script_transition_test.dart`、`script_page_motion_test.dart`、`ui_pack_contract_test.dart`；手势与生命周期新增针对性测试，规划只跑受影响的 `planner_display_gestures_test.dart` 等。普通页面改动完整 Flutter 回归交给 CI；涉及核心协议或权限时按风险扩大相关范围。

每阶段运行改动先执行相关检查，再按 [模拟器更新流程](../EMULATOR_UPDATE.md) 实际安装。宿主加示例模块使用 `scripts/update-emulator.sh --module app.ui.examples` 并选择相关 `--test`；宿主兼容后的模块调整使用 `scripts/update-emulator.sh --modules-only --module app.ui.examples`。以实际模块范围替换示例 ID，复用有效缓存，发布验收按 [发布流程](../RELEASE_WORKFLOW.md) 使用 `--force`。

设备验收必须核对实际宿主版本、模块版本与包摘要；完成打开、操作、取消、关闭、返回、再次打开和冷启动。覆盖浅深色、大字号、键盘、减少动态效果与读屏；手势重点检查横滑与列表滚动、系统返回及快速重复操作。保留数据，不卸载或清空应用。

另做一次“只更新模块”的核心目标验收：在同一兼容 APK 上改变示例的动画时长／目标缩放、松手曲线／滑动阈值与动作文案／事件，递增模块版本并使用 modules-only 更新。核对 APK 版本及摘要未变、模块版本及摘要已变；重开后观察新效果，实际点击验证新事件；模块升级前打开的旧动作菜单和回调必须失效。再用新模块版本恢复原配置以验证可恢复性，避免覆盖已发布同版本包。旧宿主不兼容测试须在独立设备／夹具完成，不降级或清空主模拟器数据。

证据保存到 `dist/verification/<日期>-module-ui-runtime/`：版本摘要、检查结果、操作记录、帧采样、资源计数和未覆盖项。缺少真机时可完成模拟器功能验收，但必须明确标记性能未验收。只交付本设计文档时执行文档检查，无需更新 APK 或模块。
