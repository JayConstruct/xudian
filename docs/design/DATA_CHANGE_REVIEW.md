# 实际数据变更审核

UX-06 的首批实现位于 `client/lib/core/module_host/data_change_review.dart`，由 `host_dialogs.dart` 接入。审核界面只解释宿主准备好的计划，不读取当前数据库重新推算，不改变权限、确认或提交规则。

## 摘要与对比

识别包含非空 `planId` 与完整合法 `writes` 的冻结计划。每条写入包含模块、数据空间、集合、记录 ID、`before` 与 `value`，且记录身份一致。按前后数据分为新增、修改、删除和内容未变：先展示影响模块数与增改删总数，再展示记录名称和字段对比。

记录名称优先使用计划内的 `title`、`name`，缺失时保留真实 ID。模块没有展示名称元数据时保留模块 ID；集合和字段名称沿用原始声明，不猜测业务含义。顶层字段逐一比较，区分字段不存在与 JSON `null`，嵌套对象及数组展示完整前后值。删除使用文字及强调色说明，摘要排列将删除放在前面，但执行顺序仍为原计划顺序。

首屏最多展示 20 条记录，每条先展示 12 个变化字段，其余字段可展开。超过 20 条时明确总数和剩余条数，所有删除仍计入总览；“全量原始详情”保留完整计划、全部记录、结果及字段，不以摘要替代原始审核内容。未来模块可增加业务名称元数据，当前不新增或推断摘要协议。

长字段值先显示字符数与展开入口，展开后保留完整内容。审核中的 `SelectableText` 关闭自身滚动，由外层审核容器负责竖向滚动；正文仍可选择、复制。2026-10-13 真机复验发现应用的弹性滚动规则会让文本内部没有滚动范围的区域抢占拖动，因此安装审核、数据审核与原始详情统一采用此规则。回归使用实际 `AppScrollBehavior`，从正文发起拖动验证下一模块／记录及全量 JSON 尾部可达，并逐字校验完整 manifest 复制结果。

## 回退与事务

合法的空写集显示“没有实际数据变化”；未识别的结构、缺失字段、额外写入字段或不一致的身份整份回退到原始详情，并明确无法生成可靠摘要。模块包和临时授权审核没有合法数据计划时沿用原始信息，不宣称没有数据变化。

确认只授权当前冻结计划，取消返回 `false` 且不提交。提交前由现有权限与记录／集合快照校验拒绝已过期计划，需要重新准备并重新审核；界面不自动接受冲突、不重建写集、不绕过确认。安装审核与 AI 或模块的数据审核继续遵守各自边界，本轮不减少必要确认。

## 验证范围

2026-10-16 增加可选的日常操作确认模式：模块调用 `ui.review(planId, {title,message,confirmLabel,acknowledgement?})`，主界面显示任务等业务对象及操作前后结果，不默认展开模块、集合、字段和操作记录。原 `DataChangeReview` 完整保留在宿主拥有的“查看变更详情”内；实际删除仍明确提醒，未知计划结构继续原始审核。模块文案只解释当前预览，实际授权、确认与提交仍以宿主冻结的计划为准。

风险确认勾选项初始未勾选，确认按钮在勾选前禁用。同一个对话框可完成超截止安排的明确确认，避免业务确认后再次弹出底层审核。旧调用、安装及授权审核保持原行为。

摘要与界面回归覆盖新增、修改、删除、无变化、未知结构、冻结快照、字段移除与 `null`、大量记录、长嵌套数据、窄屏大字号，以及真实数据库取消与提交冲突。执行数量及命令见 [第二批验证](../VERIFICATION.md#2026-10-13-商店布局弹窗与数据审核第二批完善)。后续 ARM 真机与模拟器已验证课表创建摘要、系统时区及取消后数量／当前选择保持，新增设备范围见 [真机验收](../VERIFICATION.md#2026-10-13-arm-真机显示与体验验收)。Windows 与实际读屏仍待验收。
