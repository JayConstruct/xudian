# 任务规划第三阶段：可见区渲染与大批候选

日期：2026-10-15。依据 [规划方案](../design/PLANNER_UX_REDESIGN.md)，接续 [第二阶段](PLANNER_UX_STAGE2.md)。规划模块源码1.3.0；宿主API1.25.0与任务模块1.5.1继续兼容。

## 本轮改动

- 图形区建立按日和局部拥挤组划分的几何缓存，滚动只构建可见日期／时段及缓冲区的块，不在每个滚动帧重新解析、排序全部任务。跨午夜分段保留同一任务标识，长占用滚动到中段时仍有可点击标签。
- 拖动与拉伸开始后保留源控件直到释放，避免源块滚出可见区时手势中断。密集占用用合并绘制及局部选择入口，某处拥挤不会把全天任务都折叠；清单按需构建。
- 待安排候选每页100项，服务允许1–200项；先按截止筛选、稳定排序，再分页。页码、总量及上一／下一页入口可见；日期范围和筛选变化回第一页，空尾页自动回到有效页。
- 选择跨页和筛选变化保留，明确提示包含其他页或筛选外任务，并提供清空。单次最多200项。所有选择交给排程服务统一校验；分页和筛选不影响下方已安排及只读占用。
- 普通图形移动按原UTC起止的实际持续时间计算新结束，避免跨夏令时导致隐式增减时长。未安排任务使用预计时长；详情精确编辑起止仍能明确改变时长；拉伸保持只改结束的语义。开始时刻存在时区歧义仍拒绝。
- 拖动预览若超截止，提示需要确认，不能只显示合法状态而掩盖期限问题。最终落下继续执行服务校验与既有审核。
- 撤销先校验全部关联任务版本，再检查真正恢复的执行位置。原位置出现新任务、课程或手动忙碌时，阻止整体撤销并保持当前状态。交换排除本次恢复任务各自的当前位置，再校验最终整体；不把“时间已过去”作为撤销障碍。只撤销文字和删除新建任务不引入占用，因此不额外阻止。
- 非法显示日期保留原视图和输入错误提示，避免把无效日期写入页面状态后无法继续使用。

## 验证

新增大规模用例以28天672项安排验证挂载卡片少于80，并验证横纵滚动后可见任务、跨午夜长占用、密集组与独立任务分离、手势源元素在自动滚动中保留、超截止提示。服务分页以208项候选跨三页验证无遗漏、无重复，截止筛选不改变任何已安排占用。

夏令时覆盖纽约回拨前后实际120／180分钟保持、显式详情起止编辑及秒精度边界；撤销覆盖新任务、课程和手动忙碌冲突、交换整体恢复、过去时段、仅描述变更及课程读取失败的原子拒绝。

自动化验证全部通过：

- 看板交互26项；672项任务、28天、320×600视口下，初始挂载48张卡片／144个任务表面，滚动到第21天20时后为35张／105个。任务表面包括卡片、占用带和拉伸容器；测试上限分别为80和240。
- 规划服务22项、撤销冲突7项、UX与既有规划回归组合30项；Python测试25项。
- Flutter静态分析、仓库检查、模块架构检查和差异空白检查通过；本地候选模块构建成功。

Widget数量测试不等同于真机帧率；首次几何索引仍需处理全部输入。

- 真机帧率、长时间拖动和大规模真实数据体验尚未验收。
- 插入顺延的搜索范围、可安排时段与上限尚未明确，本轮不实施隐式缺省策略。
- 有限生成器、持续规则新语义、完整规则分类、显示跨午夜区间归属、完整关闭后的草稿恢复和外部可写来源继续后续阶段。
- 现有宿主审核保留；未引入免审核提交或AI调用。

本轮只修改源码与本地候选模块，不安装设备、不更新预装资源、不发布。
