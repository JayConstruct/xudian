# 任务规划性能优化验收

日期：2026-10-16。范围：原生看板的滚动、相同数据重建及规划模块的数据读取。设计与交互保持 [任务规划重设计](../design/PLANNER_UX_REDESIGN.md) 的约定。

## 改动

- 长块信息的滚动平移、裁切由绘制层直接跟随表格滚动，不再为普通信息行创建独立收起动画或因显隐阈值重建文字。仅窄列简称的一行／两行切换更新布局；命中、语义和裁切使用同一位移。文字子树隔离重绘，隔离范围仅自然高度的信息列。
- 普通时间刻度保持静态，拖动起止刻度单独更新。背景网格作为静态子树隔离重绘。
- 看板保留日期解析、文字行高、日期列表、占用索引、范围外任务计数等有界缓存。真实任务列表、日期、显示范围、缩放、字号和主题变化仍正确刷新。
- 宿主重复构建同一个不可变脚本树时，复用看板输入列表的映射；避免忙碌状态、底栏等宿主变化让所有任务重新解析。新脚本结果采用新的输入，数据更新不会沿用旧快照。
- 规划模块1.4.5复用同一次服务调用内已读取的任务快照，减少重复范围读取和时区转换。历史和已有安排预览跳过看板查询，不使用跨请求数据缓存；操作预览、确认和撤销继续检查最新数据。

## 设备采样的解释

在同一模拟器保留数据、冷启动后，固定执行8次700毫秒往返滑动，每次间隔250毫秒，采样时不录屏。保存Android `gfxinfo framestats` 和内存信息作诊断。优化前该滑动区间的Android宿主统计为0帧，未统计到Flutter SurfaceView绘制，因此该数据不用于计算Flutter帧率、掉帧率或UI／raster耗时。实际页面另以截图、滚动录屏验收。

保留数据的3次冷启动同时记录Android首屏代理和工作区就绪时间，仅作为小样本观察；不能把整个应用启动指标直接归因为规划模块，也不据此承诺设备帧率。

| 3次冷启动观察 | 构建132 | 构建133 |
| --- | --- | --- |
| 工作区就绪p50 | 1493ms | 1401ms |
| 工作区就绪最大值 | 1566ms | 1580ms |
| Android首屏代理p50 | 1056ms | 969ms |

最大就绪耗时未降低，小样本不据此下整体启动性能改善结论。稳定收益以原生工作量和桥调用对比为准。
