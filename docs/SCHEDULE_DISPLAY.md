# 课表总高度调整

课表模块 1.5.0 在「课表页面菜单 → 调整课表高度」和「课表设置 → 显示设置」提供悬浮高度面板，课表始终显示在面板下方，调整时实时预览。滑块向左压缩、向右拉高所有节次，`−1`、`+1` 两个按钮每次精细调整总高度1个逻辑像素，在上下限禁用相应按钮；日期栏保持48。以12节课表为例，默认总高度912，范围为624–1968。

每节显示高度在48–160之间，默认72。面板右上角的「关闭高度调整」隐藏面板；未保存时关闭会恢复课表的已保存高度，草稿在当前会话保留，再次打开可继续编辑。「恢复默认高度」修改草稿，点击「保存显示设置」并完成宿主数据审核后持久保存。取消审核保留草稿；「重新载入」丢弃草稿并读取已保存值。主课表的菜单可重新打开面板，设置入口每次进入也会打开面板。

高度以可选 `rowHeight` 字段保存在当前课表中，重启后保留，不同课表可以使用不同高度，JSON 备份包含此值。旧课表省略该字段时使用原来的高度，无需迁移；修改节次数时，总高度随节次数调整。保存会检查显示设置是否被外部修改，避免覆盖其他页面的设置。

通用悬浮面板由宿主API 1.5.0提供，需先更新客户端，再导入 [独立模块包](../dist/modules/app.schedule.xmodule)。面板内可滚动，关闭按钮始终可见，未被面板遮挡的课表继续支持滚动和课程点击。调高或关闭面板不改变课表视口大小。紧凑课程标题保留1.4.1的最大高度限制，完整信息仍可通过详情查看。

验证：49项课表、宿主UI、包安全及滚动导航回归测试全部通过，覆盖微调每次总高度1、上下限、实时预览、关闭恢复、再次打开、两种入口、320×500与1200×800视口的1.6倍字体，以及既有保存/审核/重启/导入行为。静态分析和生产架构检查通过。

已在 `emulator-5554` 覆盖安装客户端build26和课表1.5.0，实际验证了精细调整、关闭/重新打开、设置入口和重启，未改写已有912的高度。安装记录见 [schedule-floating-install.json](../dist/verification/schedule-floating-install.json)，[悬浮面板截图](../dist/verification/android-schedule-floating-height.png)与[手动关闭截图](../dist/verification/android-schedule-floating-closed.png)。
