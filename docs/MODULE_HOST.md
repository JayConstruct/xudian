# 序点脚本模块宿主

自定义 UI 包、公共组件契约、模块专属风格、模拟预览与恢复见 [公共 UI 与界面包](UI_COMPONENTS.md)。UI 包复用 v3 安装／更新流程，但不启动 JavaScript 工作线程。

生产入口为 `client/lib/app/app.dart`，只注册受保护的模块管理界面。任务、基础任务视图、AI 和 UI 示例来自 `.xmodule`；课表仅在 `dist/modules/app.schedule.xmodule` 分发，不进入 Flutter 默认资源。卸载记录是持久状态，重启不会恢复已卸载模块。设置、外观、布局、安装审核、权限审核与恢复保持为宿主界面。

## 构建和验证

常用检查、模块打包和客户端构建统一见 [开发指南](../DEVELOPMENT.md)。模拟器使用 [更新脚本](EMULATOR_UPDATE.md)，只改业务模块时无需重建 APK。`build_packages.py` 生成确定性 ZIP；改变首次安装资源时才使用 `--defaults` 并审阅资源清单。相同 ID + version 不能对应不同原包摘要，源码发生变化必须增加版本。

QuickJS NG v0.17.0 源码固定在 `packages/xquickjs/src/vendor`，构建钩子编译本机原生库，模块携带 UTF-8 JavaScript 源码，不接受引擎字节码或外部原生库。Linux 使用 GCC；Android 使用 Flutter 工具链提供的 NDK，Windows 使用 CBuilder/Windows 线程桥接。构建产物包含原生引擎，安装脚本包不需要重新编译客户端。

## 包格式与来源

包中 `package.json` 的 `packageFormat` 为 2，登记除自身外的全部文件路径、字节数和 SHA-256；`module.json` 的 `formatVersion` 为 3。总包上限 16 MiB、单文件 2 MiB、256 个文件。目录越界、重复路径、符号链接、加密、未登记文件、CRC/大小/摘要不一致均拒绝；解压过程中实施容量限制。

市场 Ed25519 签名覆盖规范 JSON `{packageFormat,release,files}`，核验可信发布者、审核状态和发布者绑定。资源包另外检查构建摘要；本地未签名包必须经宿主明确展示来源后确认。活动包按原始 ZIP 摘要存入不可变目录，原始来源与版本记录保留。旧 JSON 的转换结果单独登记 `derivedFrom`，不继承或冒充原始签名。

模块定义、SDK 和示例见 [MODULE_SDK.md](MODULE_SDK.md)。宿主 API 版本为 `1.10.0`，接受兼容的 pub_semver 约束，例如 `^1.0.0`、`>=1.0.0 <2.0.0`，模块版本支持预发布与构建标识；依赖可以用模块 ID 字符串或 `{moduleId,version}` 声明版本范围。服务使用 `{moduleId,serviceId,majorVersion}`，实体引用使用 `{moduleId,collection,id}`。使用工具栏、填满视口的时间网格和 `clock.local` 的模块应声明 `^1.1.0`，使旧宿主明确拒绝尚未支持的界面能力。使用单顶栏贡献、分组设置行、时间输入及自适应面板的模块应声明 `^1.2.0`。使用公共组件节点、组件目录或 UI 包的模块应声明 `^1.6.0`。

## 运行和权限

原生线程只执行已登记的包内 ESM 与 `@xudian/sdk`。不开启 QuickJS 的 libc/操作系统模块。C 桥接仅提供不透明句柄和 JSON 消息队列，异步操作由 Dart 宿主返回消息并推进 Promise。

当前每个脚本模块使用计算、交互两个工作线程及各自的运行时，各 32 MiB JavaScript 堆，合计 64 MiB。声明式 UI 包不创建工作线程或 JavaScript 堆。这是与初始“一模块一个运行时”方案的实现差异：业务命令与可能长期等待确认的界面工作流分开，避免互相阻塞；脚本不能共享二者的内存，数据通过宿主服务交换。每个运行时栈 512 KiB、每次连续执行 1 秒；计算请求 10 秒。界面交互等待不受 10 秒计算期限限制。原生取消标志中断循环，停用同时关闭工作线程、订阅、授权和 HTTP 请求。

引擎在 App 进程内运行，是能力与资源隔离，不是操作系统级安全沙箱。

调用者身份由实际实例绑定。依赖、页面参数和脚本自填 `_host` 都不授予调用权。跨模块服务必须声明精确的 `services.query:<ref>` / `services.command:<ref>` 权限，或经宿主授权。授权默认 30 分钟、最多 20 次写入，提交重新检查过期、撤销和实例代数。事件订阅精确限定发布模块和事件类型。规则仅接收其声明发布者的提交后事件，继承深度和循环轨迹，限制深度 8。

HTTP 仅 HTTPS 或 localhost/127.0.0.1/::1 上的 HTTP，关闭重定向，连接 10 秒、读取 30 秒、总请求 60 秒，请求和响应各 1 MiB。安全输入框写入凭据，脚本只拿句柄；宿主检查模块和连接地址，再注入 Bearer 认证。密钥读取失败提示重新配置。

## 数据和提交

`host_collections`、`host_records`、`host_indexes` 为通用集合/JSON/声明索引，记录及集合分别有修订号。兼容的标量筛选、排序与分页在 SQLite 中执行，只解析请求页的记录；类型兼容检查按集合修订号缓存。混合类型、非 ASCII 排序、复杂值和暂存写集保留 Dart 过滤与排序语义。声明索引仍用于唯一性校验，尚未实现按业务字段索引加速查询，详见 [公共 UI 的性能说明](UI_COMPONENTS.md#性能与验证)。

业务命令读取快照并返回 `{writes,events,result}`。准备阶段禁止 HTTP、交互、文件和真实写入；子命令共享暂存写集，后续步骤能读到前序结果。宿主生成不可变计划，绑定调用者、请求 ID、参与者版本/空间/实例、授权和完整内容。

提交进入短 SQLite 事务，核验记录基线和范围查询的集合基线，写入 JSON、索引、设备计数、操作日志、事件 outbox 和幂等结果。任何一项失败整体回滚。事务不跨脚本执行或外部等待。事件只在提交后派发。计划在内存中保留，重启后的未提交计划必须重新准备；同一个存活计划重复提交返回原结果。

模板与规则使用同一套准备/提交机制。自定义字段归扩展模块自身，针对通用 EntityRef；停用扩展后不显示字段，原数据保留。

## 迁移、更新和恢复

数据库从 schema 1 升至 2 前，使用 SQLite backup API 生成 `xudian_v9.sqlite.before-host-v2.sqlite`。数据复制有完成标记，不新增业务事件或操作日志。任务、项目、标签、关联、字段、规则历史、AI 普通配置、历史、设备标识和计数保持；任务、项目、字段值及规则记录的时间戳保存 UTC 字符串并保留原瞬间；原表保留原表示。旧密钥只沿用安全存储别名。

旧业务表、旧模块原源码/签名/来源/版本仍保留为迁移档案；生产入口不运行旧控制器。旧 v1/v2 的活动及历史源码通过相同确定性转换器生成 v3 产物。布局保留窄/宽配置、入口 ID 和未知挂载；已知 taskId/projectId 另外补充 EntityRef，用于通用实体有效性校验。

更新先验证、写入按摘要寻址的不可变文件，再暂停相关实例，复制候选数据空间并运行受限迁移；验证全部记录、重建索引后，在数据库事务内切换活动包/数据指针，再发布注册表。失败恢复旧指针对应实例。启动以数据库为准，删除未提交候选空间和临时文件；文件系统与 SQLite 并非共同原子事务。

停用保留数据；卸载默认保留数据与历史；彻底删除是另一个明确审核入口。彻底删除会移除模块安装记录、全部版本包、所有数据空间与快照、操作和执行历史、该模块的原始迁移记录及凭据，并从模块列表消失。依赖它的模块只停用，其他模块拥有的任务、课程和数据继续保留；独立的旧迁移备份文件不删除。宿主只保留最小删除标记，阻止默认安装或迁移重试自动恢复，用户仍可明确重新安装，此时使用全新数据空间。兼容回退保留当前数据。不兼容回退必须在模块管理中选择快照恢复，恢复前把当前数据保留为新快照，避免静默丢失升级后的写入。新规则执行与旧规则档案可在同一界面查看，保留重试来源；当前可用规则可以重试失败记录。模块定义与文件源码入口复用隔离预览、摘要绑定审核及更新流程，不依赖 AI 包。受保护的宿主设置与恢复入口不能被业务模块卸载或替换。

`assets/modules/retired.json` 声明退出默认分发的模块。完成默认安装与旧来源迁移后，按模块执行一次保留数据卸载并登记处理标记；依赖它的活动模块停用但保留数据。新安装不创建这些模块，商店过滤在线或缓存目录中的旧条目。历史版本与明确的手动文件恢复仍保留，不是永久禁止安装。

## 课表与教务扩展

`packages/modules/app.schedule` 定义课表、课程、安排、单次变更、来源和导入批次，全部使用通用集合。第一周周一按民用日期计算；显示从周日开始只改变页面范围。每个课表独立作息、IANA 时区；行范围 `[start,end)`，重叠课程均显示。支持明确周次、取消、换地点/节次、跨周移动和临时课程。

ScheduleImportDraft v1 以调用实例与来源范围组合隔离来源。稳定 sourceId 优先，缺失时按完整规范内容去重；上次来源/本地当前/来源当前进行三方差异，冲突由用户选择。重复导入保留本地删除标记，局部和空结果不清空课表。配置也保存来源基线并参与三方比较。JSON 备份格式独立版本化，不含凭据或会话，导入新建时重分配本地实体 ID。

适配器声明 `services.command:app.schedule/schedule.import.prepare@1`，准备草稿后导航到 `app.schedule.home`，上下文提供 `importPlanId`。课表页通过 `services.adopt` 接受仅自身集合、需要自身确认的计划，展示实际变更并由宿主审核后提交。适配器不能直接提交；原调用身份仍用于来源映射，数据基线和参与者实例重新核验。课表页面公开 `importers` 挂载槽位。

正方通用脚本兼容和 Android 登录 WebView 由独立模块提供，见 [拾光导入兼容](SHIGUANG_IMPORT.md)。真实学校登录尚未验收；自动刷新、提醒、课程拖动、同步和公开市场服务端仍未实现。

## 验收记录与限制

实际检查范围和历史证据见 [验证记录](VERIFICATION.md)。旧行为回归测试保留在 `test/support/legacy_app*.dart` 的测试专用夹具中；这些测试证明原行为基准仍成立，不能代替新生产链验收。新 `host_*`、`script_*`、`schedule_*`、`legacy_host_*` 测试直接执行真实 QuickJS 和新生产界面。

AI 外观/布局/导航工具来自受保护的 app.host 服务，布局草稿和审核期间基线变化会拒绝提交。自定义字段编辑、明确清除、类型校验、启停可见性以及模板/规则组合均进入新生产链；模板和规则定义通过通用模块源码编辑器修改，旧记录继续可查。UI 示例保留原页面/入口 ID、公开槽位、模拟交互和位置保留声明；Flutter 组件与旧界面仍需要逐项视觉核对。高级审核展示源码、旧/新定义和实际预览，当前为结构化内容展示，尚非专门的逐行差异编辑器。所有运行平台实际验收需分别完成，Linux 测试不能替代 Windows 或 arm64 真机。

宿主高级源码编辑器当前面向 UTF-8 文本文件；包含二进制资源的模块须通过外部包工具修改并重新导入，原包和资源不会由编辑器静默删除。

课表的滚动、显示设置及导航统一见 [课表](SCHEDULE.md)，具体界面协议见 [SDK](MODULE_SDK.md)。
