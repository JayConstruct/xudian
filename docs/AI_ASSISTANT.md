# 全局 AI 助手与布局编辑：整合方案

实现核对日期：2026-10-06。当前实现是应用内部的全局悬浮插件，不是 Android 系统级悬浮窗，不申请跨应用控制或无障碍权限。

## 已实现的交互

- 内置 `app.ai` 注册 `globalOverlay`，核心在根导航器外渲染悬浮入口。关闭 AI 模块会移除悬浮界面、撤销本次授权并取消请求；不删除任务或布局。
- 悬浮入口可拖动；点击展开面板，跨应用内部页面保持可用。最小化不等于停止，可重新展开查看进度；停止执行和撤销授权是独立操作。
- 默认模式使用对话和类型化工具，支持任务查询、创建、标题／优先级／日期修改、完成状态、应用内页面打开、外观设置和入口编排。高级模式复用声明式模块生成、JSON 编辑、Diff 和人工安装确认，不运行任意代码。
- 普通授权需要批准每组操作；有限委托在指定权限及项目范围内自动执行。授权只在内存保留，默认30分钟到期，最多20次操作；每次请求最多8轮模型请求和24个工具调用。到期、用尽或重启后需重新授权。
- 支持的任务、外观和布局修改提供本次请求期间的条件撤销；用户修改过目标后拒绝覆盖。创建任务和页面导航不能由助手撤销。完成状态撤销恢复布尔状态，不恢复原完成时间。停止、重新授权、下一次发送或重启会清除临时撤销信息，不删除已提交结果。

## 数据与权限边界

发送描述及界面元数据需要用户授权；分享任务字段与允许任务写入分别选择。任务分享只包含标识、标题、优先级、日期和状态，不发送备注、完整本地快照、密钥或数据库。项目选择器读取本地项目，不向模型自动发送这些项目。

工具依次经过已启用插件检查、限时授权／项目范围检查、参数白名单检查和 `ModuleContext` 权限检查。AI 使用 `app.ai` 自己的 `tasks.read / tasks.write / ui.register`，不使用系统权限，也不借用被打开页面的权限。数据返回和等待模型后重新检查执行代次，撤销授权后不继续调用后续工具。

项目范围约束助手的直接操作；任务变更仍会发布既有领域事件，可能触发用户已经启用的自动化规则。规则继续以各自权限执行，助手授权不是规则权限的替代品，撤销助手的单次修改也不会自动补偿规则的后续效果。

API Key 保持在系统安全存储，仅由传输层用于认证，不进入模型消息或 SQLite。端点仍遵守远程 HTTPS、本机 loopback HTTP 的原有约束。默认使用 Chat Completions 原生 `tool_calls`；传输适配器有显式 JSON 兼容选项，但不会在失败后自动重放写入。

当前不提供删除、归档、移动任务、修改备注／标签、修改模型连接／权限、文件／系统操作、任意 SQL、Dart、JavaScript 或 shell 执行。模型输出与任务／模块元数据都视为不可信输入，不能扩大权限。

## 操作一致性

任务写入在同一事务内对比完整任务快照，避免 SQLite 时间戳同秒变化导致误覆盖。修改后快照在事务内捕获，仅用于本地撤销条件，不发送给模型。任务变更和日志仍原子提交，事件仍在提交后发布。

外观与布局使用数据库事务中的 compare-and-set，而非仅比较缓存。审批后目标有变化就拒绝执行，不悄悄套用旧提案。同组同一对象应合并为一次写入，重复工具调用 ID 不重复创建任务。

布局工具与手动编辑共用 `UiLayoutController.saveIfUnchanged`。助手不自动覆盖已打开编辑器的未保存草稿；审批可打开布局草稿检查，但仍需明确保存。只更新选定窄／宽屏配置中的指定入口，保留其他入口、不可用挂载及另一屏幕配置。公开／私有槽位、内容类型、固定位置和上下文要求由现有组合协议校验；循环、容量、深层嵌套等诊断在预览中展示。

操作按顺序执行，不是跨任务／设置／布局的一次大事务。后续失败时保留已完成结果，记录未完成及未执行项，不自动重试创建，也不宣称整组已回滚。取消不能撤回已经提交的操作；停止后以执行记录及实际页面为准。

页面打开通过宿主根导航器进行，不模拟点击、不主动关闭表单；当前有阻塞弹窗时要求先处理弹窗。已登记的页面以新路由打开，不保证切换已有工作区选中状态，也不承诺恢复所有页面内部状态。

## 本地记录与恢复

对话显示记录及执行状态保存在本机 `ai.assistant.history`，保留最近80条消息和100条执行记录，不做云同步。它不是加密备份，也不是可靠后台任务队列；分享的描述／任务内容可能出现在本地对话中，清空不会撤销实际变更。

重启只恢复可见记录，不恢复授权、待批准参数、模型上下文、临时撤销或执行线程。有中断标记时说明不会自动重放。运行中的前后台生命周期、进程被杀和网络失败不支持无损恢复或无人值守定时执行。

## 布局设置优化

编辑器采用固定工具栏、紧凑入口列表和单一属性检查器；宽屏并列，窄屏按需打开检查器。分组显示数量并可折叠，兼容目标与前后锚点可搜索，提供箭头／顶部／底部／前后移动，不依赖拖拽。窄屏和宽屏仍分别保存，主导航最大数量不含“更多”。详细交互见 [UI 组合](UI_COMPOSITION.md)。

## 后续顺序

1. 真机和 Windows 验证：键盘、文字缩放、面板位置、模型 tool calling 兼容性、屏幕阅读器与快捷键；增加结构化执行指标，不上传业务正文。
2. 扩展有测试的工具目录：项目查询与创建、搜索、任务移动／标签／备注；破坏性或外部操作保留强制独立确认，不能由普通委托绕过。
3. 强化执行计划：持久化操作 ID、幂等键、任务级检查点与人工恢复选择；完成跨资源补偿设计后才提供更完整撤销和恢复，不能直接重放旧模型请求。
4. 高级开发工作台：模块测试／沙盒预览、声明式 UI 组件补全、安装前验收、版本回滚。继续走现有权限／提案边界，不升级成任意代码执行器。

设计参考 CopilotKit 的前端工具与人工介入、LangGraph 的中断／检查点，以及 AG-UI 的事件表达；当前没有引入这些框架或额外 Python 服务，使用既有 Dart／Riverpod／CommandBus 架构。参考项目：[CopilotKit](https://github.com/CopilotKit/CopilotKit)、[LangGraph](https://github.com/langchain-ai/langgraph)、[AG-UI](https://github.com/ag-ui-protocol/ag-ui)。
