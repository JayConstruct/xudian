# UI 设计入口

在[看图文件夹](看图目录/)里，先选功能，再选所属模块和页面，文件名就是界面状态。例如打开“项目推进 → AI 助手 → 项目 AI 拆解”，可看到草稿和审核两张图。同一页面的状态由不同模块提供时，各状态放在对应模块下。

[打开离线看图页](看图目录/00-看图目录.html)，点击功能分类即可浏览，也可先按所属模块筛选。图片贴着画布左侧，按可用宽高等比显示。用方向键或侧栏底部的按钮翻图，选“1 张”逐张浏览，选“3 张”按组浏览。目录最后一组显示剩余图片，继续向右进入下一目录，向左可返回。宽屏最多并排显示三张，悬停置顶，滚轮缩放。

点击图片或翻页即可选图。侧栏底部可复制原文件名、本机绝对路径或“Codex 定位”。定位文本含页面标识、模块、状态和原图的仓库相对路径。点击状态名称可直接打开原图。[页面与设计稿映射表](PAGES.md)列出审核进度和尚待补图的页面。

## 本轮审核

打开看图页，选「查看本轮」。评论栏默认在右侧，可以换到左侧或收起。「同屏图片」按图号列出画面中每张图及其评论，「本轮全部」可查看整轮，点击分组标题跳到对应图片。每组都有自己的输入框；点「标注位置」后在对应图上定位，再发表评论。每条评论独占一个紧凑矩形框。图上和评论行使用相同的位置与序号，例如「左①」指左图的第一条评论；整轮列表中未显示的图使用图号。评论区可独立滚动，底部的翻图和复制按钮固定。未评论的图按没有修改意见处理。

结束时，首页的「复制本轮评论」可将意见粘贴回对话。「保存评论文件」可将 `本轮评论.json` 存到网页旁的 `design/看图目录/`，或将导出的文件直接附到对话。浏览器单独保存当前图片版本的评论；复制或导出后即可交给改稿人。

按评论改稿时，读取本轮评论文件或对话，核对原图路径和摘要，对照标注位置修改对应设计及受影响的状态，再替换现行图片并生成网页。生成器同步清理目录内评论文件中已替换版本的条目；重新打开或刷新网页时，被替换版本的旧评论也会从浏览器移除。其他图稿的评论继续保留。

提交设计稿时，先把原图登记到 [PAGES.md](PAGES.md)，再更新 [current-review.json](current-review.json)。`title` 填本轮审核名称，`images` 按审阅顺序列出全部原图的仓库相对路径。一次审核可跨页面和模块；修订时把变更项换成新原图，保留本轮其他图稿。当前没有待提交的轮次时，清单可填 `{}`。

运行 `python3 scripts/design_artifacts.py gallery` 重新生成网页，打开首页核对本轮图数和原图。交付设计稿时，回复中仅粘贴命令输出的单行 WSL 文件地址。

## 按页面查询

在仓库根目录运行以下命令。可使用中文页面名、别名、英文标识或已有的 UI 编号。名称支持部分匹配。

```bash
python3 scripts/design_artifacts.py query 设置首页 更多 编排入口
python3 scripts/design_artifacts.py query --category 项目推进
python3 scripts/design_artifacts.py query --category 课表与教务 --pending
python3 scripts/design_artifacts.py query 新建任务 课表 --json
```

不指定名称时列出全部页面。`--pending` 筛出有待完善说明的页面。只检出 Git 文档时也能查询页面，尚未下载到本机的原图会标注“本机缺图”。

## 维护页面名称与待完善项

在 [PAGES.md](PAGES.md) 的相应分类中一页一行。使用稳定的小写英文标识，中文名称沿用界面标题，别名用“、”分隔。每个状态用 `[状态](相对图片路径)` 登记，多张用 `<br>` 分开。缺图的页面保留名称，在“待完善”栏写明缺少的状态。

同一页面的同一状态只登记现行稿。保留独立的空态、主题、屏幕尺寸和操作中状态。修订时核对状态、批次选稿和确认记录，再更新对应链接。当前待审稿明确标为“待审”，用户确认后更新审核状态。

“功能分类”按使用场景填写，“所属模块”填写提供页面的模块 ID。内置设置和通用控件填“宿主”，只有方案文档的页面可填“仅规划”。如果个别状态由其他模块提供，在该图的链接标题里填写模块 ID，例如 `[完成复盘](相对图片路径 "app.views.today")`。图稿或归属变动后，在本机运行 `python3 scripts/design_artifacts.py gallery` 同步分类文件夹中的相对链接和离线看图页。

## 风格来源

整体配色、圆角和图标沿用宿主公共组件，具体规则见[界面设计规范](../docs/ui/DESIGN_SYSTEM.md)。普通内容用标题、留白和细分隔线分组，浮层和导航使用阴影。浅色和深色主题保持相同的信息层级。悬浮胶囊导航参考 FlClash v0.8.99。各页面的布局与操作以[页面表](PAGES.md)中的对应状态为准。

## 稿件存储与校验

大幅界面变更按[设计审核流程](../AGENTS.md#大幅新增或修改-ui)提交单界面图稿。页面稿放在 `design/<功能名>/`，风格稿放在 `design/styles/`。同一原图供页面表和看图目录共同引用。

```bash
python3 scripts/design_artifacts.py new --page settings --brief '设置首页的布局与交互状态'
python3 scripts/design_artifacts.py new styles --brief '整体视觉风格'
```

原图和同名 `.prompt.txt` 放在功能目录下，使用创建命令返回的批次编号作为前缀，修订时递增版本。批次目录 `.batches/<批次>/` 内的 `manifest.json` 记录工具、参考来源、选稿理由和摘要。参考材料放入 `references/`，交互说明与生成依据放入 `notes/`。确认选稿时将 `status` 设为 `selected`，在 `selection` 中登记每张获选图的 `source` 与 `reason`。

```bash
python3 scripts/design_artifacts.py index design/settings/.batches/<实际批次>
python3 scripts/design_artifacts.py check design/settings/.batches/<实际批次>
python3 scripts/check_docs.py --check-local
```

## 历史、删除与验收

新稿取代原状态后，移除旧图、配套提示词及过期的审阅包，同步更新批次清单、页面表和看图目录。若同批次仍有现行状态，保留其原图和生成依据。删除记录只登记路径、摘要与原因。

实现状态以源码为准，模拟器截图与验收记录保存在 `dist/verification/`。已发布文档的精选参考放在 `docs/design/`。录入设计稿时使用合成示例或已授权的必要材料。
