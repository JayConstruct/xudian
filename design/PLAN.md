## 逐项设计的交付内容

每项先明确用户目标、信息层级、主要操作及进入/退出路径，再设计页面与必要状态。常见能力复用，复杂自定义区域保留模块实现自由度。

| 内容 | 要求 |
| --- | --- |
| 页面结构 | 标明主信息、次信息、主操作、可折叠内容和导航关系 |
| 关键状态 | 正常、空数据、加载、错误、提交中、成功与重试；按页面补齐离线或权限受限 |
| 输入与草稿 | 中文组合输入、键盘遮挡、取消/返回、再次打开、失败后保留内容 |
| 动画 | 写明触发、方向、终态、中断/反向和减少动画行为；静态图片不作为动画实现证明 |
| 适配 | 首轮以 Android 窄屏为主，同时检查大字号、低高度、深色和宽屏展开规则 |
| 权限与数据 | 宿主显示真实影响；模块内容不替代授权，不把用户隐私写进设计参考或示例 |
| 来源与状态 | 参考、提示词、稿件、选择和实现状态分别记录，不把设计稿当作已实现页面 |

视觉依据固定为已选融合 v02：采用图中的日程与单日规划布局，沿用旧版配色、圆角与现有矢量图标。页面通过模块声明和宿主通用组件表达；已有组件不足时再扩展通用配置，并记录宿主兼容范围与 APK 更新要求。业务规则以实际模块为基准，需要改变时另行记录。

安装与授权页面应展示发布者、现行模块权限、兼容范围及真实数据影响，复用现有包校验、审核和恢复流程。

## 先完成的连续流程

UI-01 至 UI-06 组成首条连续任务流程：日程/规划 → 新建 → 可选重复与批量设置 → 预览/必要确认 → 任务详情。共享日期、草稿、返回与错误状态从开始就统一考虑，避免逐页设计后再拼接。

UI-05 沿用现有真实数据审核，UI-13、UI-16、UI-18 和 UI-19 分别细化当前授权、安装和恢复流程。业务模块关闭、故障或更新失败时，宿主设置、模块管理与恢复入口保持可达。

## 稿件与验收管理

新稿直接使用根目录 [design/](README.md)：跨页面风格原图放 `design/styles/`，页面原图放 `design/screens/ui-XX/`，同名完整提示词放在原图旁。批次元数据在各自 `.batches/<批次>/` 下。实际开始设计前运行：

```bash
python3 scripts/design_artifacts.py new ui-01 --brief 'UI-01 日程首页：本轮目标、关键状态与参考来源'
```

使用命令返回的实际批次编号作为原图文件名前缀，修订递增 `v01`、`v02`，不覆盖旧稿。来源和决策保存在该批次 `references/` 与 `notes/`；获选在清单记录原图及理由。交付前执行 `index` 和 `check`，需要随文档保存的精选副本放 `docs/design/selected/` 并记录摘要。完整规则见 [设计稿规范](../docs/DESIGN_ARTIFACTS.md)。

设计、交互原型、运行实现和设备验收分别记录。只有修改运行代码或模块时才按仓库约定更新模拟器并走到具体页面；本清单和目录整理不改变运行产物。
